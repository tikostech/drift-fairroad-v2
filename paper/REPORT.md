## Final configuration and protocol

- **Case base:** `case_base_v2.npz`, 500 valid models (16,000 cases) from 14 runs: 8 clean and 6 with one client absent (client dropout), 98 SL features per probe image, 32 probe images.
- **Comparison:** k=5 nearest valid cases per probe image, rounds r±1 of training progress.
- **Calibration:** held-out valid scores (leave-one-run-out) normalised by their round's median; one cut at the 0.99 quantile × 1.1, chosen as the most sensitive setting with held-out FPR ≤ 0.5% (achieved 0.4%). Coverage rule on.
- **Gate policy (v6):** a round's client updates are decided together; at most 1 rejected per round, most anomalous first. Checkpoints are traced but not gated (`--sl-gate-scope clients`).
- **Capture runs** trace every model without gating and are re-scored offline. Valid models for FPR and AUROC negatives come from leave-one-run-out over the case-base runs.
- Replicates are independent runs (fresh initialisation and data shuffling); no fixed RNG seed.

False rejections above count honest client updates (the same number for every version) plus checkpoints with no malicious update; the checkpoint count varies by version because it depends on how many attacker updates each gate let through. Same-denominator rate, honest client updates only: v1 11/270, v2 0/270, v3 17/270, v4 0/270, v5 3/270, v6 1/270.

Reading the comparison: every version was run under identical conditions, 3 runs per condition. Against the original gate (11/270 honest updates rejected), the revised versions ranged from 0/270 (v2, v4) to 17/270 (v3); differences of a few rejections between them are within run-to-run variation, so the versions are not a monotonic sequence of improvements. The outlier is v3: training froze in 2 run(s) -- live_v3_sign_flip_s1 (checkpoints rejected 8 rounds in a row), live_v3_sign_flip_s2 (checkpoints rejected 8 rounds in a row) -- so the honest clients kept training from a stale model and were rejected in turn. That is the failure the checkpoint stall guard (v4 on) prevents. The final gate (v6) does not gate checkpoints at all, which removes that risk; its 1/270 false rejections and 64/90 attacker updates caught are in line with the best revised versions.

What changed and why:

- **Case base:** 14 valid runs instead of 2, including client-dropout runs, because excluding an attacker turns the global model into a 2-client average the original base had never seen.
- **Calibration:** the original threshold (worst held-out model × 1.25, per round) let one unusual valid model set the threshold for three rounds; pooled, median-normalised calibration uses all held-out models together.
- **Rejection budget:** at most one update rejected per round. Rejecting every update signals drift, not a majority of attackers, and can freeze training.
- **Checkpoints traced, not gated:** across v1–v5 the checkpoint gate caught 16 poisoned checkpoints and rolled back 9 honest-only ones; the client gate stops most poison first.

## Threats to validity (state these in the paper)

- One dataset, one small CAE, 3 clients, 1 attacker, 10 rounds; replicates vary initialisation only.
- Weak attacks (sign flip ×1, noise σ=0.5, inverted training) barely change the model on this data; the gate is an anomaly detector and passes most of them. Report detection alongside harm.
- Rounds 1–2 are weakly gated: clients start round 1 from their own random weights (they skip the initial global download), so the first FedAvg averages unrelated networks and the valid spread is wide.
- The case base is specific to the probe set, model and FL configuration; any change requires rebuilding it.
- The rejection budget assumes fewer than half the clients are malicious; with it, a flagged attacker can be admitted in a round where an honest update scores higher.
- The case-base runs are also the source of held-out valid models (leave-one-run-out); there are no separate clean test runs. The live clean runs of each gate version are fresh.
- The "fixed validation set" (inherited from `evaluate_cae.py`) is client_1's training shard, not held-out data. Excluding the attacker up-weights that shard, so gated MSE can fall below clean MSE; compare conditions relative to each other, and report a held-out split in the paper if possible.
- Ablation: round-aware comparison is what raises detection; matching per probe image did not help (pooled images scored higher TPR). The live gates use the per-image variant.

## Figure captions (suggested)

- **Fig. `scores_by_round`:** Gate score relative to threshold (log scale) per round. Grey band: 5–95% of held-out valid models. Lines: median over spoofed models across runs. Dashed: threshold.
- **Fig. `quality_by_round`:** Validation MSE of the global model in force per round, attacked runs with the final gate and without a gate (mean; shaded: range over runs), against clean runs (grey).
